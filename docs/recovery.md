# 维护与恢复

## 退出和重新进入

点击右上角房屋图标，或长按屏幕，选择“退出到 Kindle”。这会恢复正常 Kindle 界面和 USB 存储处理。

退出后用 KUAL → Home Assistant 重新进入。重启会再次自动启动面板。

## 禁用自动启动

退出面板后 USB 连接，在设备 `nativeha/` 目录新建名为 `disable-autostart` 的空文件，**不带扩展名**。重启后保留 Kindle 主界面。移除该文件后，下次重启恢复自动进入。

若程序无响应，可以长按电源约 40 秒重启，再用 USB 放入禁用文件。启动任务没有自动崩溃重启循环；通过电脑 USB 启动时，会等待用户分区重新可用后再尝试运行。

## 日志

设备 `nativeha/diagnostics/`：

- `startup-install.log`：开机任务安装与根文件系统恢复记录。
- `autostart.log`：启动器与 KOReader 包装脚本输出。
- `last-screen.png`：当前启动首次刷新后的原生屏幕截图。

KOReader 的 `crash.log` 记录 Lua 错误和正常退出码。日志和截图仅在本地保留，不提交到源码仓库。

PW1 的 BusyBox 功能较少。脚本保持精简 shell 语法；例如此实测系统没有 `command` 指令。KOReader 包装脚本中某些较新 Kindle 服务的 Unknown job 提示不影响 PW1 面板启动，应结合最终画面、Lua 日志和退出状态判断。

## 更新

先在电脑构建、检查，退出原生面板后再通过 USB 更新。部署脚本会在电脑备份原文件、读回校验，并保留已有服务器配置。不要把示例配置覆盖到已配对的实际设备。HA 集成更新后按 HA 的集成更新流程重新加载，涉及 Python 代码时通常需要重启 HA。

设备密钥不位于 USB 用户分区，USB 文件备份不是系统镜像。需要重新配对时使用 HA 编辑器生成新的短期文件；移除集成会撤销全部配对。
